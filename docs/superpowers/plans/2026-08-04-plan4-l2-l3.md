# Plan 4: L2 Scene / L3 Persona Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the L2 Scene Diaries (scene_blocks/*.md narrative documents) and L3 Persona (persona.md user profile) layers, wired into mcp-server's PipelineManager with the L1→L2→L3 scheduling cascade.

**Architecture:** New modules in `@mymore/core`: `record/l2-scene.ts` (SceneExtractor: reads L1 increment, LLM consolidates into narrative scene files, UPDATE>MERGE>CREATE strategy, heat management, `[DELETED]` soft-delete, scene_index.json), `record/l3-persona.ts` (PersonaGenerator: LLM writes persona.md via structured content, incremental evolution, four-layer scan). mcp-server's PipelineManager gains L2/L3 scheduling (L1 done → advance L2 timer; L2 done → trigger L3; cold-session 24h stop; L3 serial queue). **Design simplification vs reference:** the reference has the LLM use file read/write/edit tools (reference §4.2/§5.2); mymore keeps it lighter — the LLM outputs structured content in one call, and the ENGINEERING side does the file read/write (scene_blocks/, persona.md). This avoids building an LLM tool-calling loop while preserving the narrative output.

**Tech Stack:** TypeScript, `@mymore/core` (L1 reader, LLMRunner, config), Node fs, vitest.

## Global Constraints

- Node >= 22.14. LLM calls via `LLMRunner` (built Plan 3) — NO new deps.
- **Hard prerequisites from Plan 3 final review (MUST land first):**
  1. `L1Record` gains `metadata?: Record<string, unknown>` field (Plan 4 needs `metadata.activity_*` time fields from L1 episodic extraction).
  2. `EMBEDDING_DIMS` no longer hardcoded 1536 in bootstrap — derive from `llm.embeddingModel` config or first embed call; fail loudly on mismatch.
- **Scene files** (`scene_blocks/*.md`): META frontmatter (created/updated/summary/heat) + narrative sections (核心叙事 with Trigger→Action→Result, 演变轨迹, 待确认·矛盾点). Filename: alphanumeric/CJK/`-`/`_`/`.` only.
- **scene_index.json**: engineering-side `syncSceneIndex()` scans and rebuilds (LLM never sees it).
- **L2 strategy** (reference §4.2): UPDATE (preferred) > MERGE > CREATE (last resort, max 1 new scene per batch, must read-check ≥2 most similar). MERGE → `[DELETED]` mark old file. Heat: new=1, update old+1, merge sum+1.
- **L3 persona.md**: ≤2000 chars, four-layer scan (Base/Interest/Interface/Core), Archetype + Chapter 1-4, incremental evolution (first/incremental), read-back validation.
- **L3 trigger** (reference §2.3): P1 request_persona_update (L2 `[PERSONA_UPDATE_REQUEST]` out-of-band signal) / P2 cold-start / P3 first scene / P4 threshold `memories_since_last_persona >= triggerEveryN`.
- **Scheduling cascade**: L1 done → advance L2 timer (only earlier, never later; `max(now+delayAfterL1, lastL2+minInterval)`); L2 done → arm L2 maxInterval + trigger L3; cold session (inactive >24h) stops L2 timer; L3 global serial (concurrency=1) + pending dedup.
- Tests use `mkdtempSync(tmpdir())` + fake LLM; never touch `~/.mymore` or make real LLM calls.
- TDD: write failing test → verify fail → implement → verify pass → commit. Commit per task.

- [ ] **Step 3: Implement pipeline-manager.ts L2/L3 cascade**

Per reference §2.2/§2.3:
- Add fields: `lastL2At`, `lastActiveAt`, `l2TimerTarget`, `l3Pending`.
- `advanceL2Timer()`: `l2TimerTarget = Math.max(now + delayAfterL1, lastL2At + minInterval)`.
- `armL2MaxInterval()`: `l2TimerTarget = now + maxInterval`.
